# SweepSketch

Reference implementation, P4 programs, C++ throughput harness, and packet-record
dataset for the paper *SweepSketch: Detecting Carpet-Bombing Attacks Before They End*.

This repository contains code and data only. The manuscript and the result tables are
not included; the tables are regenerated by the commands below.

## Layout

```
code/
  1_reference_implementation/   Python reference implementation and experiment drivers
  2_baselines_p4/               P4 implementations of the nine comparison baselines
  3_throughput_cpp/             C++ per-packet insertion-path throughput harness
  4_dataplane_deployed_p4/      Deployed Tofino-2 data plane (counting/reporting subset)
  5_cpp_detector/               C++20 bit-exact detector and benchmark harness

database/
  attack/                       101 gzipped CSV packet records + SHA256SUMS.txt
```

## Dataset

`database/attack/` contains 101 gzipped CSV files (25,860,949 packets), one row per
packet:

```
ts,src,dst,proto,sport,dport
1780286476.261322,45.142.193.150,1.182.230.94,17,65333,26009
```

| Directory | Files | Packets | Contents |
|---|---:|---:|---|
| `normal_single24/` | 71 | 6,618,743 | Real captures, one destination /24 each, 10 attack types |
| `natural_multi24/` | 2 | 962,959 | Real captures spanning several /24s |
| `synthetic_multi24_by_timestamp/` | 13 | 8,658,144 | Multi-prefix samples interleaved by timestamp |
| `synthetic_multi24_shuffled/` | 15 | 9,621,103 | Multi-prefix samples with shuffled timestamps |

The files contain packet metadata only: no payloads, link-layer headers, or capture
metadata. `database/attack/SHA256SUMS.txt` lists the checksum of every file.

## Benign corpora

The benign datasets are public. Download and place them under `database/benign/`:

| File | Source |
|---|---|
| `CIC-IDS-2017-Benign.pcap` | CIC-IDS-2017 (UNB Canadian Institute for Cybersecurity) |
| `CIC-IoT-2023-Benign.pcap`, `-Benign1.pcap`, `-Benign2.pcap`, `-Benign3.pcap` | CIC-IoT-2023 (UNB) |

The optional backbone stress test (`exp9`) expects `database/benign/202607051400.pcap`.

## Requirements

- Python 3.10+; the reference implementation uses only the standard library
  (`tqdm` is optional for a few baseline drivers).
- C++20 compiler for `code/3_throughput_cpp` and `code/5_cpp_detector`.
- Intel Tofino-2 and SDE 9.7.1 (`bf-p4c`) for the P4 programs.

## Quick start

```bash
cd code/1_reference_implementation
python3 run_sweep.py selfcheck      # synthetic self-check, no data needed
python3 run_sweep.py exp1           # static detection (needs attack CSV + CIC benign)
```

Results are written to `results/` at the repository root (created on first run).

The loaders accept `.csv`, `.csv.gz`, `.pcap`, and `.pcapng`, so decompressing the
dataset in place changes nothing downstream.

## Experiment commands

Run from `code/1_reference_implementation`:

| Command | Paper item | External data |
|---|---|---|
| `python3 run_sweep.py calibrate --all-benign --sample-k 1` | calibration | benign corpora |
| `python3 run_sweep.py exp1` | static detection | attack CSV + CIC benign |
| `python3 run_sweep.py exp2` | source-spoofing immunity | attack CSV + benign |
| `python3 run_sweep.py exp3 --budgets 512,1024` | memory grid | attack CSV + benign |
| `python3 run_sweep.py exp4` | dynamic timeline | attack CSV + benign |
| `python3 run_sweep.py exp5` | attack-type matrix | attack CSV + benign |
| `python3 run_sweep.py exp6` | ablation grid | attack CSV + benign |
| `python3 run_sweep.py exp7` | component mechanisms | attack CSV + benign |
| `python3 run_sweep.py exp8` | adversarial grid | attack CSV + benign |
| `python3 run_sweep.py exp9` | backbone scale stress test | backbone trace |
| `python3 run_sweep.py real` | real holdout validation | 30 holdout CSV + benign |
| `python3 run_sweep.py iot` | five-dataset static | attack CSV + CIC-IoT benign |
| `python3 run_sweep.py compare` | baseline comparison | attack CSV + benign |

## C++ detector

The C++ detector implements the same state machine as the Python reference and is used
for the per-packet throughput numbers.

```bash
cd code/5_cpp_detector
make
./build/detector --gen-synth /tmp/synth.bin --n 200000 --prefixes 1000 --seed 1
./build/detector --bin /tmp/synth.bin --alarms alarms.csv --max-pkts 200000
./build/detector --bin /tmp/synth.bin --bench --repeats 3 --max-pkts 200000
```

`--pcap FILE` accepts a packet capture directly; `--alarms OUT.csv` writes the alarm
stream. The `pyref_v2.py` script mirrors the reference implementation for comparison.

## P4 data planes

Require Intel Tofino-2 and SDE 9.7.1.

```bash
cd code/4_dataplane_deployed_p4     # deployed counting/reporting subset
# build with p4_build.sh, then load setup_ports.py / setup_tables.py through run_bfshell.sh

cd ../2_baselines_p4/<baseline>     # nine comparison baselines
./deploy_<baseline>.sh build|run|deploy|clean
```

## Notes

- The deployed data plane implements the counting/reporting subset; the decision state
  machine runs on the control plane.
- This repository is anonymized for review: it contains no author names, affiliations,
